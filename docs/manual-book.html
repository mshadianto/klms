1. Tentang KMLS

KMLS (Knowledge Management & Learning System) adalah aplikasi web satu-halaman (Single Page Application) yang mensimulasikan platform terpadu untuk mengelola tiga domain utama dalam pengembangan sumber daya manusia:

📚 Knowledge Management

SME, knowledge map, CoP, aset pengetahuan, learning paths, skill matrix, Q&A, analytics.

🎓 Learning & Development

Pengajuan pelatihan end-to-end: dari draft, approval HR, eksekusi, sampai laporan dan harvesting.

⭐ Talent Management

9-Box mapping, talent pool, succession planning, workflow promosi.

Tujuan

  • Menjadi visual reference untuk konsep KM 4-pilar dan TMS 3-stage dalam konteks BUMN/Lembaga.
  • Mendemonstrasikan integrasi alur pengajuan pelatihan ↔ aset pengetahuan ↔ kompetensi pegawai.
  • Menjadi titik awal eksplorasi UX/UI sebelum investasi pada platform enterprise.

Bukan apa

  • Bukan sistem produksi — tidak ada backend, tidak ada multi-user, tidak ada autentikasi.
  • Bukan SaaS — semua data tersimpan di localStorage browser pengguna.
  • Bukan produk resmi BPKH (lihat halaman disclaimer).

2. Arsitektur Singkat

Struktur file

klms/
├── src/
│   ├── App.jsx        ← seluruh aplikasi (~3.400 baris)
│   ├── main.jsx       ← React entrypoint
│   └── index.css      ← Tailwind directives
├── public/
│   └── CNAME          ← custom domain marker
├── mockups/           ← HTML mockup statis (referensi desain)
├── index.html         ← Vite shell
├── vite.config.js     ← base: '/'
└── .github/workflows/
    └── deploy.yml     ← auto deploy ke GitHub Pages

Mengapa single-file?

Seluruh modul, primitive UI, seed data, dan state management berada di src/App.jsx. Pendekatan ini dipilih supaya prototipe mudah dibaca, mudah di-fork, dan mudah dideploy tanpa banyak file moving parts. Untuk produksi sebenarnya, file ini harus dipecah per-modul (lihat Catatan rilis).

State model

KMLS memiliki satu state tree global bernama data yang dipegang oleh komponen KMLSApp dan diturunkan ke setiap modul. Modul yang melakukan perubahan menerima callback onUpdate(newData) dan mengembalikan seluruh objek pengganti (immutable update). 

KMLSApp (data state)
  ├── Sidebar           (read-only data untuk badge counts)
  ├── TopBar            (read-only data untuk global search)
  ├── <ActiveModule /> ({ data, onUpdate, showToast, onNavigate })
  └── AppFooter

Pilar Knowledge Management

  1. SME Development — identifikasi & pengembangan Subject Matter Expert.
  2. Knowledge Map — pemetaan domain & expertise.
  3. Community of Practice — pembentukan komunitas berbagi.
  4. Knowledge Asset — dokumen, video, SOP, lesson learned.

Stage Talent Management

  1. Acquisition — 9-Box mapping untuk mengidentifikasi posisi setiap pegawai.
  2. Development — talent pool untuk mengelola star & high-potential.
  3. Alignment — succession plan & workflow promosi.
Catatan teknis: Tidak ada router (react-router), tidak ada reducer (redux/zustand), dan tidak ada API call. Semua "navigasi" adalah pergantian state view yang menentukan modul mana yang di-render.

3. Instalasi & Menjalankan

Prasyarat

Node.jsv18 atau lebih baru (LTS direkomendasikan)
Package managernpm (bawaan Node) atau pnpm/yarn
BrowserChrome / Edge / Firefox / Safari versi terbaru
RAM minimum2 GB
Koneksi internetHanya untuk install dependency dan deploy

Langkah instalasi

  1. Clone repositori: git clone https://github.com/mshadianto/klms.git
  2. Masuk ke folder: cd klms
  3. Install dependency: npm install
  4. Jalankan dev server: npm run dev
  5. Buka browser ke http://localhost:5173/

Perintah lain

PerintahKegunaan
npm run devMenjalankan server pengembangan dengan hot reload.
npm run buildMembuat build produksi di folder dist/.
npm run previewPreview hasil build produksi secara lokal.

Akses versi live

Anda tidak perlu menginstal apapun untuk mencoba KMLS. Buka langsung di browser:

https://klms.mshadianto.id/

Tip: Karena seluruh data disimpan di browser, mencoba versi live tidak akan mengganggu data orang lain. Setiap browser punya state-nya sendiri.

Reset data ke kondisi awal

Ada tiga cara mereset data KMLS:

  1. Lewat menu Pengaturan → Reset Data di dalam aplikasi.
  2. Buka DevTools (F12) → tab Application/Storage → hapus key kmls:appdata:v2.
  3. Hard reload dengan menghapus seluruh site data dari browser settings.
Hati-hati: Reset bersifat permanen dalam browser tersebut. Semua bookmark, rating, komentar, dan pengajuan yang Anda buat akan hilang dan kembali ke seed data.

4. Mengenal Antarmuka

Layout KMLS dibagi menjadi empat area:

1. Sidebar (kiri)

Menampung seluruh navigasi modul, dikelompokkan menjadi empat seksi: Utama, Knowledge Management, Talent Management, dan Sistem. Beberapa menu menampilkan badge angka di sebelah kanan, yang menandakan jumlah item yang membutuhkan perhatian (misal: pengajuan pending, pertanyaan terbuka).

Sidebar dapat dilipat menjadi mode collapsed (hanya ikon) dengan menekan tombol di header sidebar — berguna untuk layar kecil atau memaksimalkan area konten.

2. TopBar (atas)

Berisi:

  • Judul & subtitle modul aktif — diambil dari konfigurasi PAGE_META.
  • Global search — pencarian lintas entitas (pegawai, aset, SME, pengajuan, pertanyaan). Klik hasilnya untuk langsung lompat ke modul terkait.
  • Tombol notifikasi — dummy, sebagai placeholder untuk pengembangan ke depan.
  • Avatar pengguna — selalu menampilkan user aktif (Sopian Hadianto, ID p001).

3. Area konten (tengah)

Tempat modul aktif di-render. Setiap modul memiliki struktur yang konsisten: header dengan tombol aksi → filter/search lokal → daftar/tabel/grid → detail modal (jika item diklik).

4. Footer (bawah)

Memuat tiga elemen wajib:

  • Kredit developer dan tautan ke kontak.
  • Disclaimer amber bahwa aplikasi ini bukan produk resmi BPKH.
  • Versi aplikasi dan tahun copyright.
Catatan: Warna amber pada footer disclaimer adalah pilihan desain yang disengaja — jangan diganti slate/abu-abu karena disclaimer harus visually prominent.

6. Pengajuan Pelatihan

Workflow end-to-end dari draft sampai laporan dan harvesting aset.

Tujuan

Mengelola siklus hidup pengajuan pelatihan: pegawai mengajukan, atasan/HR me-review, pelatihan dieksekusi, lalu hasil pelatihan di-harvest menjadi aset pengetahuan sehingga tidak hilang sebagai dokumen pribadi.

Status pengajuan

StatusArtiAksi yang tersedia
DraftPengajuan sedang disusun, belum dikirim.Edit, Submit
PendingMenunggu persetujuan atasan.Approve, Reject, Edit
Review HRSudah disetujui atasan, di-review HR.Approve, Reject
DisetujuiPengajuan disetujui, pelatihan dapat dijalankan.Mark Completed
DitolakPengajuan ditolak (dengan alasan).Lihat alasan
SelesaiPelatihan sudah dijalankan dan dilaporkan.🌾 Harvest Knowledge

Membuat pengajuan baru

  1. Klik tombol "+ Pengajuan Baru" di pojok kanan atas modul.
  2. Isi form: judul, jenis, tanggal mulai & selesai, biaya, penyelenggara, alasan.
  3. Pilih jenis pelatihan: Internal, Eksternal, Sertifikasi, Workshop, atau Konferensi.
  4. Klik Simpan sebagai Draft atau langsung Submit.
  5. Setelah submit, status berubah dari draft menjadi pending.

Filter & pencarian

Bagian atas modul menyediakan filter berdasarkan status dan kotak pencarian berdasarkan judul/penyelenggara. Anda juga dapat mengurutkan kolom tabel berdasarkan tanggal pengajuan.

🌾 Harvest Knowledge — fitur kunci

Saat pengajuan masuk status Selesai, akan muncul tombol "🌾 Harvest". Klik tombol ini untuk membuka modal Knowledge Harvest, yang akan membantu Anda mengubah hasil pelatihan menjadi aset pengetahuan permanen.

  1. Pilih tipe aset yang akan dibuat (SOP, Pedoman, Template, Video, Case, Lesson Learned).
  2. Isi judul, tags, dan deskripsi singkat (sudah pre-fill dari data pengajuan).
  3. Tetapkan owner dan tanggal review berikutnya.
  4. Klik "Buat Aset" — aset baru otomatis muncul di modul Knowledge Asset dengan tanda harvested.
Mengapa harvesting penting? Banyak organisasi kehilangan pengetahuan ketika pegawai pulang dari pelatihan: materi tersimpan di folder pribadi, tidak pernah dibagikan. Fitur ini "memaksa" pengetahuan kembali ke sistem.

9. Knowledge Map

Pilar 2 KM — pemetaan domain & sebaran expertise.

Tujuan

Memvisualisasikan distribusi kompetensi dan SME per domain pengetahuan, sehingga pimpinan dapat melihat area mana yang over-supplied (banyak ahli) dan area mana yang knowledge gap (kurang ahli).

Domain pengetahuan

KMLS mendefinisikan delapan domain default:

Audit Internal
GRC
Investasi Syariah
Pengelolaan Haji
IT & Cybersecurity
Risk Management
Compliance
Sukuk

Visualisasi

Untuk setiap domain ditampilkan:

  • Heatmap warna — gradasi violet, semakin pekat semakin banyak SME.
  • Daftar SME aktif di domain tersebut.
  • Jumlah aset pengetahuan ber-tag domain itu.
  • CoP terkait (jika ada).
  • Gap indicator — segitiga amber bila jumlah SME di bawah ambang.

Cara membaca knowledge gap

  1. Domain dengan 0–1 SME → high risk, butuh succession/training segera.
  2. Domain dengan 2–3 SME → medium, masih aman tapi perlu pengembangan generasi berikutnya.
  3. Domain dengan ≥ 4 SME → sehat, fokuskan pada retention dan cross-skilling.
Bridging: Domain di Knowledge Map dipakai juga oleh modul Knowledge Asset (lewat tags) dan Ask the Expert (lewat auto-routing pertanyaan). Tetap konsisten dalam penamaan domain saat menambah data baru.

10. Community of Practice (CoP)

Pilar 3 KM — komunitas lintas-divisi yang berbagi minat & praktik.

Tujuan

Memformalkan komunitas berbagi pengetahuan yang berjalan organik. Setiap CoP punya seorang lead (biasanya SME senior), jumlah anggota, frekuensi diskusi, dan engagement score.

Metrik engagement

  • Anggota — jumlah pegawai yang tergabung.
  • Diskusi per bulan — frekuensi thread/forum dalam satu bulan terakhir.
  • Engagement (%) — formula sederhana = rata-rata partisipasi aktif anggota.
  • Next event — tanggal event/diskusi terjadwal berikutnya (atau "belum dijadwalkan").

Cara membaca engagement

  • 70%+ — sehat, komunitas hidup, butuh fasilitator menjaga kontinuitas.
  • 40–69% — perlu revitalisasi: ganti topik, undang external speaker, dll.
  • < 40% — at-risk, pertimbangkan merger ke CoP lain atau dormansi.

11. Knowledge Asset

Pilar 4 KM — repositori aset pengetahuan dengan lifecycle, rating, dan knowledge graph.

Tujuan

Menjadi library pusat untuk semua aset pengetahuan organisasi: SOP, pedoman, template, video sharing, case study, dan lesson learned. Setiap aset memiliki siklus hidup (lifecycle) dan dapat di-bookmark, di-rating, dan di-comment.

Tipe aset

TipePenggunaan
SOPStandard Operating Procedure — alur baku.
PedomanPedoman teknis/metodologis yang lebih luas dari SOP.
TemplateFormat dokumen siap-pakai (kertas kerja, laporan).
VideoRekaman knowledge session, training, atau demo.
Case StudyStudi kasus pengalaman organisasi.
Lesson LearnedPelajaran kunci dari kegagalan/keberhasilan proyek.

Lifecycle aset

  1. Draft — sedang disusun oleh owner, belum dipublikasikan.
  2. In Review — sedang diverifikasi oleh SME/divisi terkait.
  3. Published — aktif, dapat dicari, di-bookmark, dan dijadikan rujukan.
  4. Archived — diarsipkan karena sudah tidak relevan / digantikan versi baru.

Metadata yang dipertahankan

FieldPenjelasan
judulNama aset, sebaiknya deskriptif (cantumkan versi).
typeSOP / pedoman / template / video / case / lesson.
tagsMulti-tag, dipakai untuk pencarian dan heuristik knowledge graph.
ownerPegawai yang bertanggung jawab atas isi.
versionNomor versi (1.0, 2.0, 3.1, dst).
reviewDateKapan aset wajib direview ulang.
descriptionRingkasan isi aset.
ratingsUp / ratingsDownAkumulasi rating dari pembaca.
viewsJumlah kali aset dibuka.
lastViewedAtTanggal terakhir dibuka (untuk deteksi dormant).
commentsDaftar komentar pembaca.
harvestedFromJika aset ini lahir dari pengajuan pelatihan tertentu.

Tampilan utama Knowledge Asset

Modul ini memiliki dua mode tampilan: Grid (kartu, default) dan List (tabel padat). Toggle ada di pojok kanan atas.

Filter & pencarian

  • Pencarian by judul/tag/owner.
  • Filter berdasarkan tipe (SOP, pedoman, dll).
  • Filter berdasarkan status (draft, review, published, archived).
  • Filter berdasarkan tag.
  • Toggle "Hanya bookmark saya".
  • Toggle "Hanya milik saya" (sebagai owner).

Asset Detail Modal

Klik salah satu kartu aset untuk membuka modal detail. Modal ini punya empat tab:

TabIsi
OverviewDeskripsi, version history, review schedule, owner info.
CommentsDiskusi antar pembaca, dapat menambahkan komentar baru.
GraphKnowledge graph — relasi aset ini dengan SME, CoP, dan Learning Paths terkait.
ActivityAudit trail: kapan dibuat, kapan direvisi, siapa yang mengubah status.

Knowledge Graph (tab Graph)

Tab ini adalah salah satu fitur unggulan KMLS. Berdasarkan heuristik tag/division/domain, modul menampilkan:

  • Owner — pemilik aset, lengkap dengan divisi.
  • SME terkait — yang ahli di domain aset.
  • CoP terkait — komunitas yang aktif di topik tersebut.
  • Learning Paths terkait — kurikulum yang sudah memasukkan aset ini.
Catatan teknis: Heuristik ini bukan semantic search. Cocoknya berdasarkan kemiripan tag (case-insensitive) dan overlap divisi. Pada implementasi enterprise, ini sebaiknya diganti dengan embedding-based similarity.

Rating & Bookmark

Setiap aset published dapat di-rating (👍 / 👎) dan di-bookmark. Rating bersifat sederhana — bukan untuk diskualifikasi aset, melainkan untuk membantu pengguna lain menilai relevansi.

  • Bookmark — disimpan di state bookmarks, dapat dilihat dengan toggle "Hanya bookmark saya".
  • Rating — satu user satu suara (mock implementation, tidak ada deduplikasi keras).
  • Komentar — append-only, tidak ada threading, tidak ada edit.

Membuat aset baru

  1. Klik tombol "+ Aset Baru" di header modul.
  2. Pilih tipe (SOP, pedoman, dll).
  3. Isi judul, version, tags (pisahkan dengan koma), description.
  4. Set owner dan tanggal review berikutnya.
  5. Status awal default = draft.
  6. Setelah konten siap, ubah status ke review → published.

Aset hasil Harvest

Aset yang dibuat lewat fitur Harvest di modul Pengajuan Pelatihan akan memiliki field harvestedFrom yang berisi ID pengajuan asal. Modal detail akan menampilkan badge khusus 🌾 Harvested dan link kembali ke pengajuan asal.

Best practice: Tetapkan review date 6–12 bulan dari publikasi. Saat tanggal review tiba, aset akan muncul di KM Analytics → "Perlu Review" supaya tidak terlupakan.

13. Skill Matrix

Pemetaan kompetensi & gap analysis.

Tujuan

Menampilkan matriks kompetensi pegawai dalam bentuk heatmap, sekaligus membandingkan level aktual dengan role requirement sehingga muncul daftar gap yang harus diisi.

Skala level kompetensi

LevelLabelDeskripsi
0NoneBelum memiliki kompetensi.
1FoundationalMemahami konsep dasar.
2IntermediateMampu mengaplikasikan dengan supervisi.
3AdvancedMampu mandiri menangani kasus kompleks.

Tampilan matriks

Gap analysis

Modul ini membandingkan level pegawaiCompetencies dengan roleRequirements untuk jabatan pegawai. Hasilnya:

  • ✅ Match — level pegawai ≥ requirement → hijau.
  • ⚠️ Gap 1 — kurang 1 level → kuning.
  • ❌ Gap ≥ 2 — kurang 2+ level → merah, prioritas pengembangan.

Filter

  • Filter per divisi (tampilkan satu divisi saja).
  • Filter per domain kompetensi.
  • Toggle "Hanya tampilkan gap" — untuk fokus pada area yang butuh pengembangan.
Konteks integrasi: Hasil gap dapat dipakai sebagai input alami untuk pengajuan pelatihan (modul Pengajuan), penentuan path belajar (Learning Paths), atau penilaian kandidat suksesi (Succession Plan).

14. Ask the Expert

Q&A dengan auto-routing ke SME.

Tujuan

Memberikan saluran resmi bagi pegawai untuk bertanya pada SME, sekaligus menangkap jawaban berkualitas tinggi sebagai aset pengetahuan masa depan (lewat Promote to Asset).

Lifecycle pertanyaan

  1. Open — pertanyaan baru, belum ada jawaban.
  2. Answered — minimal satu SME sudah menjawab, masih menunggu konfirmasi penanya.
  3. Resolved — penanya menandai pertanyaan sudah teratasi.

Auto-routing

Ketika pertanyaan dibuat, sistem mencocokkan field domain pertanyaan dengan domain expertise SME. SME yang cocok mendapat highlight di sidebar pertanyaan, sebagai indikator "Anda sebaiknya menjawab ini".

Membuat pertanyaan

  1. Klik + Tanya di header modul.
  2. Isi judul (≤ 120 karakter, jelas dan spesifik).
  3. Body — uraian masalah, konteks, sudah mencoba apa.
  4. Pilih domain — menentukan auto-routing.
  5. Submit. Status awal = open.

Menjawab pertanyaan

SME yang relevan dapat menulis jawaban di kotak respons. Jawaban dapat di-vote oleh user lain (rating berupa angka). Jawaban dengan vote tertinggi muncul di posisi teratas.

Promote to Asset

Jika sebuah jawaban dinilai evergreen (berlaku jangka panjang), SME atau admin dapat menekan tombol Promote to Asset. Jawaban tersebut akan dikonversi menjadi aset pengetahuan baru (default tipe: Lesson Learned), dengan field promotedToAssetId terisi sebagai link balik.

Best practice: Tidak semua jawaban perlu dipromosikan. Promosikan hanya yang (a) menjawab pertanyaan umum, (b) memiliki konten substansial, (c) di-validasi minimal 2 SME.

22. Workflow End-to-End

Bagian ini menyajikan tiga skenario alur kerja yang menjadi contoh utama bagaimana modul-modul KMLS berkolaborasi. Setiap workflow melibatkan minimal tiga modul.

Workflow 1 — Pengajuan Pelatihan → Harvest Knowledge

  1. Pegawai membuat pengajuan pelatihan di modul Pengajuan. Status = pending.
  2. Atasan me-review dan menyetujui. Status = approved.
  3. Pegawai mengikuti pelatihan (di luar sistem).
  4. Setelah selesai, status diubah ke completed.
  5. Tombol 🌾 Harvest muncul. Klik untuk membuka modal harvesting.
  6. Pilih tipe aset → isi metadata → simpan.
  7. Aset muncul di modul Knowledge Asset dengan badge harvested.
  8. Aset di-publish, di-bookmark, dan di-rating oleh pegawai lain.
  9. Owner mendapat tugas review tahunan saat reviewDate tiba (muncul di KM Analytics).

Workflow 2 — Q&A → Aset → Learning Path

  1. Pegawai junior bertanya di Ask the Expert tentang sampling audit syariah.
  2. Sistem auto-route ke SME audit. SME menulis jawaban.
  3. Penanya menandai pertanyaan resolved.
  4. Admin/SME klik Promote to Asset — jawaban dikonversi ke Lesson Learned.
  5. Curator di Learning Paths menambahkan aset baru ini sebagai step di path "Onboarding Auditor".
  6. Auditor baru yang enroll path tersebut otomatis melewati pengetahuan ini.

Workflow 3 — Skill gap → Talent Pool → Succession

  1. Di Skill Matrix, terlihat divisi Investasi punya gap besar di kompetensi Sukuk.
  2. HR mengidentifikasi pegawai potensial untuk pengembangan → masukkan ke Talent Pool kategori "Future Star".
  3. Buat Learning Path "Investasi Syariah Mastery" untuk pegawai tersebut.
  4. Setelah 1 tahun, pegawai naik level kompetensi → di 9-Box bergerak ke kuadran high-pot.
  5. Saat posisi Kepala Divisi Investasi terbuka, pegawai ini muncul sebagai kandidat di Succession Plan.
  6. Eksekusi promosi via Workflow Promosi.
Kunci adopsi: Workflow akan berjalan jika setiap modul punya owner yang aktif. Tanpa owner, modul akan menjadi data terisolasi yang tidak saling berbicara.

23. FAQ

Tentang aplikasi

Q: Apakah KMLS aman dipakai untuk data sungguhan organisasi?

Tidak. KMLS adalah prototipe, tidak memiliki autentikasi, tidak punya backend, dan menyimpan semua data di localStorage browser. Data bisa hilang kapan saja jika user clear cache atau menggunakan browser lain.

Q: Data saya bocor ke mana?

Tidak ke mana-mana. Semua data tinggal di browser Anda. Tidak ada server yang menerima data, tidak ada analytics tracker, tidak ada cookie pihak ketiga.

Q: Apakah ini produk resmi BPKH?

Bukan. Lihat halaman Disclaimer Penting di awal manual ini. KMLS adalah karya pribadi MS Hadianto untuk eksplorasi konsep.

Penggunaan

Q: Bagaimana cara berbagi data dengan rekan?

Gunakan menu Pengaturan → Export JSON. Kirim file hasil ke rekan, dan rekan melakukan Import JSON di browser-nya.

Q: Bisakah saya pakai di mobile?

Bisa, layout responsif. Tapi pengalaman terbaik di tablet atau desktop karena banyak tabel dan grid dua-kolom.

Q: Kenapa user saya selalu Sopian Hadianto?

Prototipe ini single-user mode — konstanta CURRENT_USER_ID di kode hard-coded ke p001. Multi-user real time membutuhkan backend & autentikasi.

Q: Bagaimana cara menambahkan kompetensi baru?

Saat ini editor kompetensi belum disediakan di UI. Tambahkan langsung di seed data (competencies array di App.jsx), lalu reset data agar entri baru muncul.

Teknis

Q: Browser yang didukung?

Chrome, Edge, Firefox, Safari — semua versi yang dirilis dalam 2 tahun terakhir. Internet Explorer tidak didukung.

Q: Bagaimana cara melaporkan bug?

Buka issue di repositori GitHub mshadianto/klms, atau email langsung ke penulis (lihat halaman Disclaimer).

24. Troubleshooting

Aplikasi tidak menyimpan perubahan

Gejala: setelah refresh, data kembali ke seed.

  • Cek apakah browser dalam mode Incognito/Private — di mode ini localStorage dihapus saat tab ditutup.
  • Cek apakah ada extension yang memblokir storage (privacy extension).
  • Buka DevTools (F12) → tab Application → Local Storage → cek apakah key kmls:appdata:v2 ada.
  • Cek quota — jika storage penuh, write akan gagal. Lihat console untuk error.

Layar putih / blank

  • Buka DevTools console (F12). Cari error JavaScript.
  • Jika error berkaitan dengan field yang tidak ada (misal undefined.map), kemungkinan ada data lama dari versi sebelumnya. Hapus key localStorage dan reload.
  • Cek koneksi internet untuk muat asset Tailwind/lucide pertama kali (setelah itu di-cache).

Build produksi gagal

  • Hapus folder node_modules dan package-lock.json, lalu jalankan npm install ulang.
  • Pastikan Node ≥ v18.
  • Jika ada error tentang case-sensitivity (Linux vs Windows), cek apakah ada file path dengan kapitalisasi tidak konsisten.

Deploy ke GitHub Pages tidak update

  • Cek tab Actions di GitHub — workflow deploy sudah jalan?
  • Workflow hanya berjalan saat push ke branch main.
  • Pages source harus diset ke "GitHub Actions" (bukan branch).
  • Tunggu 2–5 menit setelah workflow selesai untuk propagasi CDN.

Custom domain (klms.mshadianto.id) tidak HTTPS

  • Cek file public/CNAME berisi klms.mshadianto.id.
  • Di Cloudflare DNS, record harus DNS-only (grey cloud), BUKAN proxy (orange cloud). Orange cloud memblokir validasi Let's Encrypt.
  • Tunggu hingga GitHub Pages selesai menerbitkan sertifikat (kadang sampai 24 jam).

Performance lambat

  • Hard refresh: Ctrl+Shift+R (Windows) atau Cmd+Shift+R (Mac).
  • Tutup tab lain yang berat.
  • Jika data prototipe diperbesar (misal 10.000 entry), pertimbangkan migrasi ke backend nyata.

Pencarian global tidak menemukan apa-apa

  • Pencarian mencocokkan substring sederhana (case-insensitive). Pastikan kata kunci ada di field yang dicari.
  • Bidang yang dicari: nama pegawai, judul aset, judul pengajuan, judul pertanyaan, nama SME.
  • Coba kata kunci yang lebih pendek.
